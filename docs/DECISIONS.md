# 결정 기록 (Decisions)

설계서(DESIGN.md)의 세부 결정과 그 이유입니다.

## 호출자 식별 (F1)

**D1. 호출자는 소켓 상대 PID의 프로세스 계보로 판단한다.**
Unix는 `SO_PEERCRED`, Windows는 `GetNamedPipeClientProcessId`로 상대 프로세스 PID를 얻습니다. 그 PID가 pane 루트 프로세스의 자손이면 그 pane(에이전트)으로, 플러그인 프로세스의 자손이면 플러그인으로 봅니다. 나머지는 사람(User)으로 봅니다. 토큰 방식은 쓰지 않았습니다. 같은 사용자 권한으로 도는 에이전트는 토큰 파일을 그냥 읽을 수 있어서입니다.

**D2. pane에서 빠져나간 프로세스도 pane 출신으로 본다.**
계보만 보면 에이전트가 `( kmttt pane run … & )`처럼 부모를 끊어(이중 fork) 사람으로 분류될 수 있습니다. 그래서 세 겹으로 막습니다.
1. Linux: 서버를 `PR_SET_CHILD_SUBREAPER`로 둡니다. 그러면 pane 자손 고아가 init 대신 서버 밑으로 옵니다. 계보가 pane 루트를 거치지 않고 서버에 닿으면 "unknown" 에이전트(가장 제한적)로 봅니다.
2. 모든 OS: 호출 프로세스 환경 변수에 `KMTTT_PANE`이 있으면 그 pane으로 봅니다. 일부러 지우면 피할 수 있는 보조 신호입니다.
3. 잠금 실패처럼 판단이 불가능할 때는 User가 아니라 unknown으로 봅니다(실패 시 닫힘).

서버가 입양한 고아의 좀비는 0.5초마다 회수합니다. 이때 서버가 직접 띄운 자식(pane 루트, git, 플러그인)의 종료 상태를 가로채지 않도록, 그 자식들은 같은 잠금 안에서 띄우고 등록합니다(`kmttt-pty::reaper`).

macOS와 Windows는 subreaper가 없어 다른 방법을 씁니다.
- Windows: pane 루트를 pane마다 전용 Job Object에 넣습니다. 자식은 부모를 끊어도 Job을 벗어날 수 없으므로(breakaway 미허용) `IsProcessInJob`으로 확실히 식별됩니다. 부모가 먼저 끝난 손자 프로세스도 식별하며, CI가 실제 API로 확인합니다. 계보를 따라 올라가다 터미널·데스크톱 호스트보다 WMI·작업 스케줄러·서비스 관리자를 먼저 만나는 호출자도 unknown으로 봅니다. Windows Terminal 같은 패키지 앱은 svchost가 띄우기 때문에 "있는지"가 아니라 "먼저인지"로 판단합니다.
- macOS: launchd(PID 1) 밑으로 간 고아이면서 제어 터미널이 없는 호출자를 unknown으로 봅니다. 사람이 터미널에서 친 CLI는 셸이 살아 있는 부모이고 제어 터미널도 있습니다. macOS CI에서 이중 fork + setsid 프로세스로 확인합니다.

**D3. pane 안에서 사람이 직접 `kmttt`를 쳐도 에이전트로 본다.**
사람과 에이전트를 같은 pane 안에서 구분할 방법이 없기 때문입니다. 승인은 pane 바깥 터미널, TUI 승인 패널, 웹 콘솔에서 합니다.

**D4. `--remote`는 API 명령 전부에 적용하고, 로컬 파일 명령에는 거부한다.**
`--remote`가 일부 명령에서 조용히 무시되면 `kmttt --remote prod pane run …`이 이 컴퓨터에서 실행됩니다. 그래서 API 명령은 SSH 너머 서버로 보내고, 정책·통합·플러그인·기록 검증처럼 로컬 파일을 다루는 명령은 오류로 거부합니다.

## 서버와 기록 (F2)

**D5. 세션마다 기록 폴더를 따로 둔다: `ledger/<session>/`.**
세션마다 서버가 따로이므로, 기록 폴더를 같이 쓰면 해시 체인에 쓰는 쪽이 둘이 될 수 있습니다. 기록 폴더에는 `writer.lock` 단독 잠금(OS 파일 잠금)도 걸어서, 무슨 일이 있어도 쓰는 쪽은 하나뿐입니다. 검증(`audit verify`)은 잠금 없이 읽기만 합니다.

**D6. 같은 세션 서버는 OS 파일 잠금으로 하나만 뜬다.**
"이미 떠 있나" 확인만으로는 두 클라이언트가 동시에 서버를 띄울 때 둘 다 통과합니다. `server-<session>.lock`을 `File::try_lock`으로 잡습니다. 프로세스가 비정상 종료해도 OS가 잠금을 풉니다.

**D7. 서명 키는 Windows에서 DPAPI로, 그 밖에는 0600 파일로 보관한다.**
macOS 키체인이나 Linux Secret Service는 쓰지 않았습니다. 헤드리스 서버와 SSH 원격에서 잠금 해제 대화창 없이 돌아야 해서입니다. 같은 사용자 권한을 가진 공격자는 키를 읽을 수 있습니다. 그래서 진짜 위변조 방지는 외부 반출(mirror 파일, syslog)에 기대야 합니다.

**D8. 관제 센터의 보안 이벤트 목록은 재시작 때 기록에서 되살린다.**
서버가 뜰 때 기록에서 최근 보안 이벤트 300개를 다시 읽고, "오늘 차단" 수도 오늘(UTC) 차단 이벤트로 다시 셉니다. 암호화된 기록은 화면 복원에서 건너뜁니다.

## 마스킹 (F3)

**D9. 한 번 잡은 비밀 값은 메모리에서 기억해, 문맥 없이 다시 나와도 가린다.**
`echo $API_TOKEN`처럼 값만 출력되면 형식 규칙으로는 잡히지 않습니다. 그래서 이전에 잡은 값과, 서버 환경 변수 중 비밀로 보이는 값(이름에 TOKEN, SECRET, KEY 등)을 배워 둡니다. 배운 값은 디스크에 저장하지 않습니다. 저장하면 비밀 목록 파일이 생기기 때문입니다. 재시작하면 다시 배웁니다.

**D9a. 환경 변수에서 배운 비밀은 고정하고, 출력에서 배운 비밀은 오래된 것부터 잊는다.**
출력에서 배운 값은 최대 2,000개까지 기억합니다. 상한에 닿았을 때 가장 긴 값부터 지우면, 에이전트가 무작위 문자열을 대량으로 출력해 목록을 채우는 것만으로 서버 환경 변수의 진짜 토큰을 밀어낼 수 있습니다(퍼즈 테스트에서 발견, 회귀 테스트 `flooding_output_cannot_evict_env_secrets`). 그래서 환경 변수와 설정 재적재로 이어받은 값은 고정해 지우지 않고, 출력에서 배운 값만 들어온 순서대로 지웁니다.

**D10. 화면 표시 가림(`mask_screen`)은 클라이언트에서 한다.**
서버는 원본 바이트를 클라이언트에 보내야 터미널이 제대로 그려집니다. 그래서 TUI에서 보일 때만 가립니다. `pane read`, 기록, 저장 이력은 서버에서 항상 가립니다.

## 격리 (F4)

**D11. Windows `restricted`는 Job Object 자원 제한뿐이다(강도 `low`로 표시).**
Windows에는 Landlock 같은 사용자 수준 파일 시스템 제한이 없습니다. AppContainer는 에이전트 대부분이 깨집니다. 파일 격리가 필요하면 `wsl`이나 `container`를 쓰세요.

**D12. `restricted`에서도 `/tmp`, 시스템 임시 폴더, `/dev`, 설정한 홈 하위 폴더는 쓸 수 있다.**
에이전트와 빌드 도구 대부분이 여기에 씁니다. 다른 사용자와 공유하는 `/tmp`에 쓸 수 있다는 점은 남는 위험입니다.

**D13. `restricted`에서 외부 TCP 연결은 이그레스 프록시로만 간다.**
Linux 6.7 이상은 Landlock 네트워크 규칙(ABI v4)으로 프록시 포트와 `allow_tcp_ports`에만 connect를 허용합니다. 더 오래된 커널에서는 경고만 하고 계속합니다. macOS는 sandbox 프로필의 `network-outbound`로 막습니다. Landlock은 포트만 보고 주소는 보지 않으므로, `allow_tcp_ports`에 3000을 넣으면 어느 주소의 3000이든 허용됩니다. `container`의 허용 목록은 권고 수준입니다(기본 `bridge` 네트워크는 직접 나갈 수 있음). 그래서 container pane을 띄우면 관제 화면에 `sandbox.egress_not_enforced` 알림을 띄웁니다. 완전히 끊으려면 `sandbox.container_network = "none"`을 쓰면 되고, 이때 에이전트는 오프라인이 됩니다.

**D14. worktree 워크스페이스의 기본 프로필은 `none`이다.**
worktree 워크스페이스에는 `policy.toml`의 `sandbox.worktree_profile`로 격리 프로필을 자동 적용할 수 있고, 기본값은 `none`입니다. `restricted`를 기본으로 하면 홈 폴더 캐시에 쓰는 에이전트가 처음부터 깨지기 때문입니다.

## 상태 감지

**D15. 감지 fixture는 합성 화면 + 실제 화면이다.**
에이전트 UI 특징 문구로 만든 합성 화면 20개가 있고, 95% 이상 맞혀야 합니다. 실제 Claude Code와 Codex 화면(`real-*`)은 하나도 틀리면 안 됩니다. 실제 화면 기준:
- Claude Code: 폴더 신뢰 질문과 답 뒤의 후속 질문은 blocked, 답하는 동안은 working입니다. Claude가 띄운 MCP 서버가 전면에 있어도 계보에서 `claude`를 찾습니다.
- Codex: 시작할 때 뜨는 업데이트 선택 메뉴는 질문(blocked)으로 봅니다. 기다리는 동안에도 화면을 계속 다시 그리므로 입력 칸이 보이면 idle로 봅니다.

**D16. "esc to interrupt" 같은 작업 중 표시는 아래쪽 8줄만 본다.**
화면 전체를 보면 위쪽에 남은 예전 표시 때문에 작업이 끝나도 `working`으로 남을 수 있어서입니다.

## 그 밖

**D17. 마우스로 경계선을 끌어 크기를 조절한다.**
`layout.set_ratio` API를 씁니다. 사람만 쓸 수 있습니다(Admin 등급이라 에이전트는 거부됨).

**D18. CLI 도움말은 한국어이고, 최상위 설명과 README는 영어다.**
`config.toml`의 `language`는 TUI 문구에만 적용됩니다.

**D19. 업데이트는 minisign 서명 검증을 통과해야만 설치한다.**
공개키(`assets/release/minisign.pub`)는 저장소에 두고 빌드할 때 실행 파일에 넣습니다. 공개키라 비밀이 아닙니다. `KMTTT_MINISIGN_PUBKEY`로 다른 키를 넣을 수도 있습니다. 비밀키는 저장소 Secrets(`MINISIGN_SECRET_KEY`)에 있고, 릴리스 워크플로가 모든 파일의 해시 목록(`SHA256SUMS.txt`) 하나에 서명합니다. 파일마다 서명 파일을 붙이면 내려받기 목록이 두 배로 길어져 사용자가 헷갈리므로, 서명은 목록에만 두고 `kmttt update`는 목록의 서명을 확인한 뒤 받은 파일의 해시가 목록과 같을 때만 설치합니다. 업데이트 다운로드는 내장 인증서 목록 대신 OS 인증서 저장소를 씁니다. 회사망의 TLS 검사 프록시 인증서도 믿게 하려는 것입니다.

**D20. 같은 사용자 권한의 악의적 에이전트는 `none` 프로필로 가둘 수 없다(위협 모델).**
`none` pane의 에이전트는 `ssh localhost`로 다시 들어와 자기 승인 요청을 스스로 허용할 수 있습니다. 기록에는 결정한 프로세스 계보(`kmttt ← sshd ← sshd`)가 남아 사후 추적은 됩니다. 같은 사용자 권한이면 설정 파일 수정이나 서버 재시작도 가능하므로, 이 경우에 대한 진짜 경계는 격리 프로필입니다. Linux `restricted`에서는 SSH 연결(`Permission denied`)과 설정·기록 수정이 모두 막힙니다. 승인 암호(passphrase)도 검토했지만 넣지 않았습니다. `none`에서는 에이전트가 암호 해시 파일을 바꿔 쓸 수 있어 경계가 되지 못하는데, 보안 기능처럼 보이기만 하면 오히려 해롭기 때문입니다.

## Windows 동작

**D21. Windows에서 지켜야 하는 동작.**
1. ConPTY는 시작할 때 커서 위치(ESC[6n)를 묻고 답을 받을 때까지 멈춥니다. 화면을 가진 서버가 DSR·DA 질의에 답합니다.
2. 서버를 자동으로 띄울 때 호출한 쪽의 파이프·리다이렉트 핸들을 물려받지 않도록 `CreateProcessW`로 핸들 상속 없이 띄웁니다(`kmttt … | ConvertFrom-Json`이 끝나지 않는 문제 방지).
3. Windows 서비스 밑에서 도는 자동화(CI 러너 등)는 에이전트로 분류됩니다. 기본은 엄격하게 두고, `identify.trusted_launchers`로 믿을 실행자를 지정할 수 있습니다. WMI로 만든 프로세스는 항상 에이전트로 봅니다.
4. npm으로 설치한 에이전트(Node로 실행)를 알아보도록 Windows 경로의 역슬래시를 정규화한 뒤 `@scope/pkg` 패턴과 비교합니다.
5. `agent prompt`는 붙여넣기와 Enter 사이를 띄우고, 질문이 그대로 남아 있으면 Enter를 한 번 더 누릅니다(blocked일 때는 절대 누르지 않음).
6. 에이전트가 질문(blocked)을 띄운 상태에서는 `agent prompt`를 거부합니다. 글자와 Enter가 그 질문의 답(예: 업데이트 메뉴 선택)이 되기 때문입니다. 덮어쓰려면 `--force`를 씁니다.

## 데스크톱 앱

**D23. 창 GUI는 서버에 붙는 또 하나의 사람 클라이언트로 만든다(Tauri 2 + xterm.js).**
터미널 표시는 VS Code와 같은 xterm.js(6.0.0, 저장소에 그대로 넣고 해시를 `desktop/ui/vendor/VENDOR.md`에 적어 CI가 확인)를 쓰고, 앱 껍데기는 OS 웹뷰를 쓰는 Tauri 2.12를 썼습니다. egui는 터미널 렌더러를 새로 만들어야 하고, Electron은 브라우저를 통째로 싣는 만큼 공격 표면이 넓어 뺐습니다.
- 판단은 모두 서버가 합니다. 앱은 TUI와 같은 RPC만 씁니다(서버를 띄우는 코드는 `kmttt-core::spawn`을 CLI와 함께 씀).
- 웹뷰는 앱에 들어 있는 화면 파일만 읽습니다(CSP `default-src 'self'`, 원격 스크립트·글꼴 없음, 배포 빌드에서 devtools 끔). shell·fs·http 플러그인 권한은 웹뷰에 주지 않았고, Rust 명령 중 서버 RPC는 허용 목록(`ALLOWED`)으로 좁혔습니다. `pane.run`·`pane.send`·`pane.read`처럼 다른 pane을 조작하는 메서드는 열지 않았고 테스트로 고정했습니다.
- 서버에서 온 이름·출력은 모두 `textContent`로만 화면에 넣습니다(`innerHTML` 금지). 터미널 속 링크는 주소 전체를 보여 주고 확인을 받은 뒤 http(s)만 엽니다.
- 승인 버튼은 `isTrusted` 이벤트(실제 마우스·키보드)만 받습니다. 같은 사용자의 OS 자동화 도구가 누르는 것은 막지 못합니다(D20과 같은 한계). pane 안에서 띄운 데스크톱 앱은 서버의 호출자 식별에 따라 에이전트로 분류되어 승인이 거부됩니다.
- 설정 저장은 toml_edit으로 바뀐 칸만 고쳐 주석을 지키고, 서버와 같은 검사(`Config::parse`, `PolicyConfig::parse`)를 통과해야 씁니다. 원래 파일은 `.bak`으로 남기고, 서버가 새 설정을 거부하면 되돌립니다. 보안을 약하게 하는 변경(물어보기→허용, restricted→none, 기록 수준 낮추기, 허용 도메인·포트 추가 등)은 바뀌는 내용을 보여 주고 한 번 더 확인받습니다.
- Tauri의 `freezePrototype`은 껐습니다. 켜면 xterm.js가 시작하지 못합니다. 웹뷰에 외부 스크립트를 들이지 않으므로 프로토타입 오염 경로가 없다고 보고 끈 것입니다.
- 터미널 영역이 보일 때만 화면 크기를 서버에 보냅니다. 숨은 영역의 크기(0)를 보내면 모든 pane이 줄어들기 때문입니다.
- 단축키: 복사·붙여넣기는 터미널 관례대로 `Ctrl+Shift+C/V`, 전체 현황은 `Ctrl+Shift+O`, 나누기는 `Alt+Shift+=`/`Alt+Shift+-`(Windows Terminal과 같음)입니다.
- 서버는 화면 크기를 하나만 가집니다. TUI와 데스크톱 앱을 동시에 붙이면 마지막에 크기를 보낸 쪽에 맞춰집니다.
- 터미널 질의(커서 위치 ESC[6n, 장치 속성 ESC[c 등)의 답은 서버 한 곳에서만 합니다. 화면(xterm.js)도 답하면 두 답이 겹쳐 셸에 글자가 입력되므로 화면 쪽 답은 막습니다.
- 사람이 직접(탐색기·시작 메뉴) 띄운 앱만 연결됩니다. pane 안이나 원격 자동화 도구로 띄운 앱은 서버가 `unknown`으로 보고 `client.attach`를 거부하며, 앱은 그 이유를 화면에 보여 줍니다.

## 사용량 표시·설치 고지·제거·용어

**D24. AI 사용량은 각 에이전트가 공식으로 내놓는 값만 읽는다.**
- Claude Code: 공식 상태 줄(statusLine)이 표준 입력으로 받는 JSON의 `rate_limits.five_hour`·`seven_day`(`used_percentage`, `resets_at`)를 씁니다([문서](https://code.claude.com/docs/en/statusline)). 로그인 토큰을 읽어 사용량 API를 직접 부르는 방법은 쓰지 않았습니다. 자격 증명을 건드리게 되고 공개 API도 아니기 때문입니다. 대가는 세 가지입니다: Pro·Max 구독에서만 값이 오고, 응답을 한 번 받아야 갱신되며, 사용자 상태 줄을 바꿔야 합니다.
- 상태 줄을 바꾸면 Claude Code가 "esc to interrupt" 안내를 숨겨 화면 기반 상태 감지가 약해집니다. 그래서 연결할 때 훅도 함께 연결하는 것을 기본으로 했습니다.
- 사용자가 이미 상태 줄을 쓰고 있으면 `--replace` 없이는 바꾸지 않고, 바꿀 때는 원래 것을 `usage/claude-statusline-previous.json`에 두었다가 연결 끊기·제거 때 되돌립니다. Windows에서는 상태 줄이 Git Bash나 PowerShell로 실행되므로 공백 없는 8.3 짧은 경로와 `/`를 씁니다.
- 저장하는 것은 숫자(비율·리셋 시각)뿐입니다. 이 파일은 같은 사용자가 고칠 수 있으므로 보안 판단에는 쓰지 않고 표시만 합니다.
- Codex: `~/.codex/sessions/**/rollout-*.jsonl(.zst)`의 마지막 `rate_limits`(primary·secondary)를 읽습니다. 압축 해제는 32MB, 일반 파일은 끝 4MB만 읽어 큰 기록에도 버티게 했습니다. 옛 형식(`resets_in_seconds`)은 파일 수정 시각을 기준으로 바꿉니다.
- 표시는 "남은 %" = 100 − 사용 %, 리셋까지 남은 시간은 매번 다시 계산합니다. 값이 오래됐을 수 있어 "○분 전 갱신"을 함께 보여 줍니다.

**D25. 설치 첫 화면에 개인·비상업 고지를 두고, 제거는 이 설치본이 한 일만 되돌린다.**
- NSIS 설치 프로그램의 라이선스 화면(`desktop/windows/NOTICE.rtf`)에 "김광모(Kwangmo Kim)의 비상업 개인 프로젝트, 회사 제품 아님, 무료, 보증 없음, MIT 또는 Apache-2.0, 설치하는 것, 제거 방법"을 한국어·영어로 적고 동의를 받습니다. 게시자 이름도 "Kwangmo Kim (personal project)"입니다.
- '비상업'은 이 프로그램을 팔거나 유료로 제공하지 않는다는 뜻입니다. 소스 코드 라이선스는 MIT 또는 Apache-2.0이며, 누구나 그 조건 안에서 쓸 수 있습니다.
- 설치·업그레이드 전(`NSIS_HOOK_PREINSTALL`): 이 설치 폴더의 `kmttt.exe` 서버가 돌고 있으면 묻고 `server stop` 뒤 남은 프로세스를 끕니다. 다른 위치의 kmttt는 건드리지 않습니다.
- 제거 전(`NSIS_HOOK_PREUNINSTALL`): 서버를 같은 방식으로 끄고, `integration uninstall claude-usage|claude|codex --if-this-exe`로 **이 실행 파일을 가리키는 항목만** Claude·Codex 설정에서 지웁니다. 사용자의 원래 상태 줄은 되돌립니다.
- 제거 후(`NSIS_HOOK_POSTUNINSTALL`): 설정과 보안 기록을 지울지 묻고 기본은 "아니요"입니다. 보안 기록은 사고 뒤 확인할 증거라 조용히 지우지 않습니다. 조용한 제거(`/S`)도 남깁니다.
- NSIS 설치 프로그램은 32비트라 거기서 띄운 PowerShell의 `Get-Process`는 64비트 kmttt의 경로를 읽지 못합니다. 서버는 `Win32_Process.ExecutablePath`(WMI)로 찾습니다. 매크로 안 라벨은 넣는 곳마다 ID를 넘겨 만듭니다.
- `ci/installer-windows.ps1`이 Windows CI에서 설치 → 사용량 연결 → 서버 실행 중 업그레이드 → 서버 실행 중 제거를 돌려 위 동작을 확인합니다.

**D26. 화면 용어는 터미널을 모르는 사람 기준으로 바꾼다.**
- pane → 창, agent → AI 에이전트, split right/down → 좌우로/위아래로 나누기, control center → 전체 현황, ledger → 보안 기록, verify → 기록 위변조 검사, isolation/profile → 보호 수준(보호 안 함·기본 보호·컨테이너·WSL), policy → 보안 규칙, redaction → 비밀값 가리기, command palette → 기능 찾기.
- 원래 이름(`pane.run`, `restricted`, `w2:p3`)은 괄호로 함께 보여 줍니다. 문서·CLI·설정 파일과 연결해 찾을 수 있어야 하기 때문입니다. 승인 카드는 "어느 작업 공간의 어느 창이 무엇을 하려는지"를 문장으로 씁니다.
- 도움말은 터미널 자리를 차지하지 않도록 한 줄짜리 '지금 할 일'(숨길 수 있음, 경고는 못 숨김)과 F1 가이드 창(시작하기·이걸 하려면·단축키·용어 설명·정보와 제거)으로 제공합니다.
- 모든 화면 문구는 `desktop/ui/i18n.js`에 한국어·영어로 있고, `ci/check-desktop-strings.js`가 코드가 쓰는 키가 두 언어에 모두 있는지 CI에서 확인합니다.
- 보안 점검 결과는 [SECURITY-REVIEW.md](SECURITY-REVIEW.md)에 있습니다.

**D27. 창 제목 줄은 터미널 위에 겹치지 않고, 서버가 창 높이에서 한 줄을 비워 그 자리에 그린다.**
제목 줄을 터미널 위에 겹치면 첫 줄이 가려지고, 마우스를 올릴 때만 보이게 하면 있는지 모릅니다. 그래서 데스크톱 앱은 `client.viewport`에 `header_rows: 1`을 보내고, 서버는 창마다 터미널 높이를 한 줄 줄입니다. 터미널 화면(TUI)은 이 값을 보내지 않으므로 이전과 같습니다. 두 화면이 같은 세션에 함께 붙으면 마지막에 크기를 보낸 쪽 기준이 되고, 데스크톱 앱은 자리가 비어 있을 때만 제목 줄을 그립니다.

**D28. 창별 토큰은 에이전트가 남기는 응답별 사용량을 센다. Claude Code의 상태 줄 토큰 합계는 쓰지 않는다.**
Claude Code 상태 줄의 `context_window.total_input_tokens`·`total_output_tokens`는 공식 문서상 "지금 컨텍스트에 있는 토큰"이고, 예전 버전에서는 세션 누적이어서 뜻이 바뀌었습니다. 그래서 상태 줄은 어느 창의 대화 기록인지(`transcript_path`)만 적어 두고, 앱이 그 기록의 응답별 `usage`를 메시지 ID마다 한 번씩 셉니다. Codex는 기록의 누적값 증가분을 쓰되, 창 정보를 남기지 않으므로 작업 폴더가 같은 최근 기록과 짝짓고 화면에 추정(`*`)이라고 표시합니다. 셈 기준은 두 에이전트 모두 "새 입력 + 출력"(캐시 읽기 제외)입니다. 패널을 닫으면 읽기를 멈춥니다.

**D29. 운영체제 알림으로는 승인하지 못하게 한다.**
앱이 뒤에 있을 때 승인 요청을 놓치지 않도록 Windows 알림을 띄우지만, 알림 창은 요청한 창·명령 전체·대상 같은 맥락을 다 보여 주지 못합니다. 그래서 알림에는 승인 버튼을 두지 않고 앱에서 확인하게 합니다. 알림은 Rust 쪽 명령(`notify`)으로만 띄우며 웹뷰에 알림 플러그인 권한을 주지 않습니다. 노란 띠의 Alt+Y/Alt+N도 실제 키 입력(`isTrusted`)만 받습니다.

**D30. 도구 호출 규칙은 정규 JSON과 문자열 값(이스케이프를 푼 그대로)에 함께 맞춰 본다.**
도구 입력은 정규 JSON 문자열로 기록하고 보여 줍니다. 그런데 규칙도 그 글자에만 맞춰 보면, JSON에서는 탭이 `\t` 두 글자로 적히므로 `rm<탭>-rf /`가 `\s`를 쓰는 내장 규칙을 피합니다(셸에서는 탭도 단어를 나눔). 퍼즈 테스트(`tool_policy`)를 만들며 확인했습니다. 그래서 정규 JSON 뒤에 문자열 값들을 원래 글자 그대로 덧붙인 텍스트에 규칙을 맞춰 봅니다. 정규 JSON을 그대로 앞에 두므로, JSON 모양에 맞춰 쓴 사용자 규칙은 전처럼 동작합니다.

**D31. 외부 접속 프록시는 호스트 이름에 쓸 수 있는 글자만 받는다.**
허용 목록 비교는 문자열의 끝(도메인 접미사)으로 하고, 실제 접속은 같은 문자열로 이름을 풉니다. 이름에 `#`·`@`·NUL 같은 글자가 섞이면 두 쪽이 다르게 해석할 여지가 생기므로, 영문·숫자·`.`·`-`·`_`(대괄호 IPv6는 16진수와 `:`)만 받고 나머지는 400으로 거절합니다. 요청 읽기는 퍼즈 테스트(`egress_request`)가 직접 부를 수 있게 순수 함수로 분리했습니다.
