## 주요 기능 · Highlights

- **멀티플렉서 · Multiplexer** — 에이전트(Claude Code, Codex CLI, OpenCode, Cursor CLI, Copilot CLI, Gemini CLI, Aider, 셸)마다 실제 터미널 창을 제공하고, 백그라운드 서버가 창을 관리합니다. 창은 끌어서 옮기고 크기를 자유롭게 조절할 수 있습니다. / A real terminal pane per agent, owned by a background server; drag panes to move them and resize freely.
- **보안 통제 · Security controls** — 사용자만 승인할 수 있는 정책 관문, 위변조 탐지 감사 로그, 민감정보 마스킹, 창별 격리 수준, 위험한 도구 호출을 차단하는 훅. / A policy gate with approvals reserved for people, a tamper-evident audit log, secret masking, per-pane isolation levels, hooks that block dangerous tool calls.
- **즉시 승인 · Answer from the banner** — 알림 막대에 요청 내용과 자동 거부까지 남은 시간, [이번만 허용] (Alt+Y)·[거부] (Alt+N). 앱이 백그라운드에 있으면 Windows 알림(알림에서는 승인 불가). / Request details, a countdown and Allow once/Deny on the banner; a Windows notification when the app is in the background (approvals cannot be granted from the notification).
- **토큰 사용량 · Token usage** — Claude Code·Codex의 분당 토큰, 15분 추이, 창별 사용량. 패널을 닫으면 읽기를 멈춥니다. / Tokens per minute, a 15-minute trend and per-pane usage; reading stops while the panel is closed.
- **AI 사용량 · AI usage** — 잔여 한도(%)와 초기화까지 남은 시간, 15% 미만이면 경고. / Remaining allowance and reset times, with an alert below 15%.
- **한국어·영어 · Korean and English** — 화면과 문서를 두 언어로 제공합니다. / Interface and documentation in both languages.

## 1.3.4 이후 바뀐 점 · Changes since 1.3.4

- **연동 진단 · Integration diagnosis** — `kmttt integration status`가 연동마다 왜 동작하지 않는지 정해진 사유 코드(`reason`)와 짧은 설명(`reason_text`)을 함께 보여 줍니다. 예: 설정 파일 없음·깨짐, Codex `notify`가 다른 프로그램, 훅 일부만 있음, `--chain` 대상이 없거나 거부됨, 등록 기록과 다름. 경로·프로그램 이름·인자는 보여 주지 않습니다. 기존 필드(`agent`, `installed`, `file`)는 그대로입니다. / `kmttt integration status` now gives a fixed reason code (`reason`) and a short explanation (`reason_text`) for each integration, such as a missing or broken config, a different Codex `notify`, partial hooks, or a missing or refused `--chain` target. Paths, program names and arguments are never shown, and the existing fields are unchanged.
- **식별 못 한 호출자의 감사 한도 · Audit limits for unidentified callers** — 어느 창에서 왔는지 식별하지 못한 호출자는 Codex 알림 연결 감사 한도를 창과 겹치지 않는 별도 묶음으로 세고, 요약에 식별 못 한 호출자와 서로 다른 프로세스 수를 남깁니다. / In the Codex notify-chain audit, callers KMttt cannot tie to a pane get their own limit bucket, and the summary names them and counts distinct processes.

## 파일 확인 · Verifying a download

`SHA256SUMS.txt`에 모든 파일의 해시가 있고, 이 목록이 minisign으로 서명돼 있습니다. `kmttt update`는 이 검사를 스스로 합니다.
`SHA256SUMS.txt` lists the hash of every file and is signed with minisign. `kmttt update` performs this check automatically.

```
minisign -Vm SHA256SUMS.txt -P RWSsN6lcjx/Hn8RG/c/tAQnOC1Xk3A2fOCuRT5mhX7LwEZzT9nYuU80E
sha256sum -c --ignore-missing SHA256SUMS.txt        # Windows: Get-FileHash <file>
```
