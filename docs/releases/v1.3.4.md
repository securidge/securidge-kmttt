## 주요 기능 · Highlights

- **멀티플렉서 · Multiplexer** — 에이전트(Claude Code, Codex CLI, OpenCode, Cursor CLI, Copilot CLI, Gemini CLI, Aider, 셸)마다 실제 터미널 창을 제공하고, 백그라운드 서버가 창을 관리합니다. 창은 끌어서 옮기고 크기를 자유롭게 조절할 수 있습니다. / A real terminal pane per agent, owned by a background server; drag panes to move them and resize freely.
- **보안 통제 · Security controls** — 사용자만 승인할 수 있는 정책 관문, 위변조 탐지 감사 로그, 민감정보 마스킹, 창별 격리 수준, 위험한 도구 호출을 차단하는 훅. / A policy gate with approvals reserved for people, a tamper-evident audit log, secret masking, per-pane isolation levels, hooks that block dangerous tool calls.
- **즉시 승인 · Answer from the banner** — 알림 막대에 요청 내용과 자동 거부까지 남은 시간, [허용] (Alt+Y)·[거부] (Alt+N). 앱이 백그라운드에 있으면 Windows 알림(알림에서는 승인 불가). / Request details, a countdown and Allow/Deny on the banner; a Windows notification when the app is in the background (approvals cannot be granted from the notification).
- **토큰 사용량 · Token usage** — Claude Code·Codex의 분당 토큰, 15분 추이, 창별 사용량. 패널을 닫으면 읽기를 멈춥니다. / Tokens per minute, a 15-minute trend and per-pane usage; reading stops while the panel is closed.
- **AI 사용량 · AI usage** — 잔여 한도(%)와 초기화까지 남은 시간, 15% 미만이면 경고. / Remaining allowance and reset times, with an alert below 15%.
- **한국어·영어 · Korean and English** — 화면과 문서를 두 언어로 제공합니다. / Interface and documentation in both languages.

## 1.3.3 이후 바뀐 점 · Changes since 1.3.3

- **승인 버튼과 세션 허용 안내 · Approval wording** — [허용]은 [이번만 허용]으로 바뀌었습니다. 승인 상세에는 [이 세션 동안 허용]이 어떤 요청을 언제까지 허용하는지, 쓸 수 없으면 그 이유가 한 줄로 나옵니다. 알림 막대·Windows 알림·감사 로그도 요청한 창을 `w2:p6(codex)` 같은 가공 전 표기 대신 창 이름으로 보여 줍니다. / [Allow] is now [Allow once]. Approval details say what "Allow for this session" covers and when it expires, or why it is unavailable, and the banner, Windows notification and audit log name the requesting pane instead of a raw label.
- **닫기 이름과 확인 · Closing** — KMttt X 버튼의 [창 닫기]는 [트레이로 숨기기]로 바뀌어, 터미널 창을 닫는 [창 닫기]와 헷갈리지 않습니다(동작은 같음). 탭을 닫을 때도 닫을지 확인하고, Windows에서는 창·탭·워크스페이스를 닫거나 서버를 종료하거나 프로그램을 끝낼 때 그 창에서 연 앱(VS Code, 로그인 브라우저 등)도 함께 닫힌다고 알려 줍니다. / The X button's "Close window" is now "Hide to tray" (same behavior). Closing a tab prompts for confirmation, and on Windows the close, stop-server and quit confirmations say that apps opened from those panes close too.
- **Codex 알림 연결 보강 · Codex notify chaining** — `--chain`으로 연결한 이전 알림은 WSL·콘솔 호스트·원격 셸처럼 인자를 셸로 넘기는 실행 파일을 거부하고, 실행 결과를 감사 기록에 남깁니다. 같은 창에서 반복되는 기록은 분당 한도까지만 남기고 나머지는 건수로 요약하며, 상한을 넘은 실패 기록도 건수에 포함합니다. / Chained notifiers refuse programs that hand their arguments to a shell (WSL, console hosts, remote shells) and their outcomes are audited; repeated records per pane are capped per minute and the rest are counted in a summary, failures included.
- **승인 처리 · Approvals** — 세션 허용을 쓸 수 없는 요청에서 세션 허용을 선택하면 실행을 허용하지 않고 기다리는 상태로 남기며, 이미 결정된 승인은 다시 결정할 수 없습니다. / Sending "Allow for this session" where it does not apply leaves the request pending, and an approval that was already decided cannot be decided again.
- **문서 · Docs** — 사용 가이드·README·SECURITY.md를 처음부터 끝까지 다시 검수했습니다(메뉴 이름, 제거 시 Codex `notify` 복원, Codex 연동 방법, 영어 용어, 지원 버전). GitHub에서 깨진 링크로 보이던 표기를 고쳤고, CI가 공개 문서의 빈 절·깨진 링크·한영 짝을 검사합니다. / The user guide, README and SECURITY.md were reviewed end to end; text GitHub rendered as broken links is fixed, and CI now checks public docs for empty sections, broken links and Korean/English parity.

## 파일 확인 · Verifying a download

`SHA256SUMS.txt`에 모든 파일의 해시가 있고, 이 목록이 minisign으로 서명돼 있습니다. `kmttt update`는 이 검사를 스스로 합니다.
`SHA256SUMS.txt` lists the hash of every file and is signed with minisign. `kmttt update` performs this check automatically.

```
minisign -Vm SHA256SUMS.txt -P RWSsN6lcjx/Hn8RG/c/tAQnOC1Xk3A2fOCuRT5mhX7LwEZzT9nYuU80E
sha256sum -c --ignore-missing SHA256SUMS.txt        # Windows: Get-FileHash <file>
```
